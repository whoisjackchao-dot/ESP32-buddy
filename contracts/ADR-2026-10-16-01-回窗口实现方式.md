# ADR-2026-10-16-01：Windows 上"回到 Agent 窗口"的实现方式

> 状态：**✅ 已批准（2026-10-16，采纳方案 B）** —— 决策已定；**实现未开始**（`B08` spike 见 `evidence/B08-回窗口可行性-spike.md`）。
> 关联：`Q15`、`R18`、`BTN-05`、`M6`、缺口 `B08`

## 1. 问题

产品要求按某个键**回到 Agent 所在的窗口**（上游 K2 的动作）。上游在 **macOS/Linux** 实现：按 host 决定用 deeplink（Claude App、Ghostty bundle id 等），无 host 的会话跳过。本项目主机是 **Windows**，行为必须重新定义。

## 2. 证据

| 等级 | 内容 |
| --- | --- |
| 文档级 | 上游 `docs/protocol.md`：K2 按"运行位置"决定动作；SSH/后台会话无窗口可回，跳过 |
| 源码级 | 上游 `daemon/src/source_opener.rs`（存在该职责模块；**未细读**） |
| 本项目 | 旧项目 `host/src/launcher.cpp` / `tray.cpp` 已有 Windows 托盘与进程管理经验（**未在本项目复用**；**本机无该项目，不可核**） |
| 本项目 | 缺口 `B08`：Windows 焦点/提权边界未验证 |
| **本次实测**（2026-10-16 B08 spike） | 目标窗口可稳定识别：进程 `WindowsTerminal`，类 `CASCADIA_HOSTING_WINDOW_CLASS`，标题 `OC \| <会话名>`，`MainWindowHandle` 可读 |
| **本次实测** | helper **非提权**；从**后台非前台**进程调用 `SetForegroundWindow` **结果不一致**（0.5s 内先成功、后再调用被拒 `False`）→ **不可依赖裸调用** |

## 3. 候选方案

| 方案 | 说明 | 优点 | 代价 |
| --- | --- | --- | --- |
| **A** | 打开 URL / 自定义协议链接 | 简单，跨边界小 | 不一定回到"那个会话" |
| **B** | 激活已知窗口（复用旧项目 launcher/tray 能力） | 贴合产品语义 | Windows 焦点/提权/多桌面边界不同 |
| **C** | 本阶段不实现，按键留空 | 最省，不引入风险 | 少一个功能 |

## 4. 选定 / 未选定

- **选定**：**B**（2026-10-16，用户批准）。目标窗口 = **运行 OpenCode 的终端窗口**（用户确认 OpenCode 为终端 TUI）。
- **未选定**：A、C 保留本条比较记录。
- **实现要点（B08 spike 结论）**：裸 `SetForegroundWindow` **不可靠** → host helper 内需实现**稳健激活例程**（候选：`AttachThreadInput` + `ShowWindow(SW_RESTORE)` 组合；或 `AllowSetForegroundWindow`；降级：taskbar 闪烁 `FlashWindowEx`）。**具体选择与真机复测留待 M6**。
- **切换规则**：若 B 的关键门槛（能否稳定激活目标窗口）失败，应**重新提交设计选择（评审 A）**，**不自动退回 C 或静默禁用按键**。

## 6. 边界（批准后仍不覆盖）

- 不覆盖"任意窗口定位"（B08 明确不承诺）。
- 不覆盖非 OpenCode 的 Agent（`Q12`）。
- 不覆盖远程/SSH/后台会话（无窗口可回）。
