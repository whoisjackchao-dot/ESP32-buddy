## 3. `Done` 边沿合成（B01，🔴 本节点关键）

- 上游是**事件**（`task.done` 一次性）；本项目从快照只能拿到**电平**（`idle`）。
- **规则（待产出）**：无显式 `PET_EV_TASK_DONE` 时，`WORKING/INPUT_REQUIRED → IDLE` 的**下降沿**合成一次 DONE。
- **去抖（待产出）**：`retry` 会导致抖动，需在下降沿前稳定 N ms 才认；N 是参数。
- **不承诺**：零误报 / 零漏报（明确写进契约）。

## 7. 冻结（2026-10-16，M2 状态机增量）

> 本节点先冻结 **状态机 + `done` 边沿 + 失联**；动画帧与节拍留到本节点后半段（仍待产出）。
> 依据：M1 契约 §6；上游 `display.rs` / `protocol.md`。

### 7.1 事件 → 状态

| 事件 | 目标态 | 播报 |
| --- | --- | --- |
| `PET_EV_TASK_START` | `WORKING` | — |
| `PET_EV_AGENT_INPUT_REQUIRED` | `INPUT_REQUIRED` | `PET_SOUND_INPUT` 一次 |
| `PET_EV_TASK_DONE` | `DONE` | `PET_SOUND_DONE` 一次（**显式事件，不去抖**） |
| `PET_EV_TASK_ERROR` / `PET_EV_AGENT_BLOCKED` | `FAILED` | `PET_SOUND_FAILED` 一次 |
| `PET_EV_AGENT_IDLE` | 见 7.2 | 见 7.2 |
| `PET_EV_LINK_DOWN` | `OFFLINE`（`gray=true`） | — |
| `PET_EV_LINK_UP` | 恢复进入 `OFFLINE` 前的状态（无则 `IDLE`） | — |
| `PET_EV_CARD` / `PET_EV_ANNOUNCEMENT` | 不变（M4） | — |

### 7.2 `done` 边沿合成（B01）

- `WORKING` 或 `INPUT_REQUIRED` 收到 `PET_EV_AGENT_IDLE` → **不立即**变 `IDLE`，而是记下"待定完成"；
- 持续 **`PET_DONE_EDGE_DEBOUNCE_MS`** 内无可打断事件 → 转 `DONE` 并播报一次 `PET_SOUND_DONE`；
- 期间收到 `PET_EV_TASK_START` → **取消**（视为 `retry` 抖动），**不播报**；
- 已在 `IDLE` 时收到 `PET_EV_AGENT_IDLE` → 保持不变，**不播报**；
- `DONE` 驻留 **`PET_DONE_DWELL_MS`** 后回 `IDLE`。
- **不承诺**零误报/零漏报。

### 7.3 失联

- `tick(now)` 时，若 `now - last_valid_ms > PET_LINK_TIMEOUT_MS` → `OFFLINE`（`gray=true`）；
- `last_valid_ms` 在每次 `apply` 时刷新；`tick` 首次调用把它初始化为 `now`。

### 7.4 参数（提案值，可配置，**待批准**）

| 符号 | 值 | 依据 | 状态 |
| --- | --- | --- | --- |
| `PET_DONE_DWELL_MS` | 5000 | 上游 `protocol.md`（"after 5 seconds"） | ⏳ 待批准 |
| `PET_DONE_EDGE_DEBOUNCE_MS` | 1500 | **本项目提案**（无上游证据） | ⏳ 待批准 |
| `PET_LINK_TIMEOUT_MS` | 15000 | 上游 `README`（"15 秒判定断开"） | ⏳ 待批准 |

> 双轨制：用户确认前按提案实现，且**做成可配置**（编译期 `#ifndef` 覆盖），验收文档不得当作已批准值。

## 8. 渲染半段 冻结（2026-10-16）

> 目标：满足 G1「6 态目视可辨」。立绘只有 4 帧（Normal/EyesClosed/Happy/Sad），
> `DONE/FAILED/OFFLINE` 靠帧区分；`WORKING/INPUT_REQUIRED` 靠**头顶标记**区分。

### 8.1 规则

| 项 | 规则 |
| --- | --- |
| `gray` | `pet_view.gray = true` 时整幅立绘**灰化**：按亮度权重换算后写回三通道相等（上游 `look::gray` 同法） |
| `mirror` | `pet_view.mirror = true` 时**水平翻转**：输出列 `lx` 取输入列 `LOOK_W-1-lx` |
| 头顶标记 | `WORKING` → `>`；`INPUT_REQUIRED` → `!?`；其余态**不画**标记 |
| 标记位置 | `(x + 56, y - 18)`（宠物原点左上为参考），**2× 缩放**，图案行 `bit0 = 最左` |
| 标记颜色 | `WORKING` = `0xFFFF`（白）；`INPUT_REQUIRED` = `0xFD20`（橙）（本项目取值） |
| 标记越界 | 与立绘一致：裁剪，不越界写 |

### 8.2 参数

| 符号 | 值 | 依据 | 状态 |
| --- | --- | --- | --- |
| `PET_MARK_OX` / `PET_MARK_OY` | 56 / -18 | 本项目提案（对齐上游"头顶上方"） | ⏳ 待批准 |
| 标记色 | `0xFFFF` / `0xFD20` | 本项目取值（上游用白/橙强调） | ⏳ 待批准 |

### 8.3 明确不做（本半段）

- 不做 idle 眨眼/小动作的**时间驱动**（属 `pet_engine` 的动画节拍，留待 M2 收尾或 M8）。
- 不做 `>` 的**动画**（静态即可）。
- 不改变立绘 4 帧格式。

## 9. 动画节拍 冻结（2026-10-16）

> 目标：空闲时宠物"活着"（会眨眼、偶尔发呆），且节拍可用 `tick(now_ms)` 确定性驱动（可 host 测）。

### 9.1 规则

| 项 | 规则 |
| --- | --- |
| 帧计数来源 | `pet_state` 在每次 `apply`/`tick` 记录 `now_ms`；动画相位 = `now_ms - since_ms`（进入当前状态的时刻） |
| **眨眼** | **仅 `IDLE`**：相位落在每 `PET_BLINK_PERIOD_MS` 的**末段** `PET_BLINK_MS` 内 → 视图为 `EYES_CLOSED`，否则 `NORMAL` |
| **小动作（发呆）** | **仅 `IDLE`**：相位落在每 `PET_IDLE_MOOD_PERIOD_MS` 的**末段** `PET_IDLE_MOOD_MS` 内为"动作期"；动作按 `(相位 / 周期) % 3` 轮换 `Nap / Look / Stretch`。**`Nap` → `EYES_CLOSED`；`Look` / `Stretch` 因立绘只有 4 帧，暂等同 `NORMAL`** |
| 其他状态 | 不眨眼、不做小动作（`WORKING/INPUT` = `NORMAL`，`DONE` = `HAPPY`，`FAILED` = `SAD`，`OFFLINE` = `EYES_CLOSED`） |
| 优先级 | 小动作期优先于眨眼 |

### 9.2 参数（提案值，可配置，**待批准**）

| 符号 | 值 | 依据 | 状态 |
| --- | --- | --- | --- |
| `PET_FRAME_MS_DUTY` | 125 | **本项目提案**（上游未取到；与 leisure `FRAME_MS=125` 对齐） | ⏳ 待批准 |
| `PET_BLINK_PERIOD_MS` | 1000 | 本项目提案（"大约每秒眨一下"） | ⏳ 待批准 |
| `PET_BLINK_MS` | 125 | 本项目提案（一帧时长） | ⏳ 待批准 |
| `PET_IDLE_MOOD_PERIOD_MS` | 20000 | 上游 `docs/pet.md`（"roughly every 20 seconds"） | 🟡 文档级 |
| `PET_IDLE_MOOD_MS` | 2000 | 本项目提案 | ⏳ 待批准 |

> **口径说明**：上游用**帧数**（眨眼 `frame%8`、小动作周期 40 帧）而非毫秒，但上游 duty 的帧间隔本项目**未取到**，故改用**毫秒**，以免把未知帧率当成已知。`Look/Stretch` 需要位移/道具，属 M8（巡逻/小剧）范畴，本节点不做。
