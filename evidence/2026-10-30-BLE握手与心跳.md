# B6：BLE 握手 + 心跳（GATT 0xFFE3）

- 日期：2026-10-30
- 背景：BLE 定位为**控制面**（配对/握手），数据面走 WiFi；此前只有链路层 supervision，无应用层心跳。

## 设计
- GATT 服务 `0xFFE0` 新增状态特征 **`0xFFE3`**（notify，需加密 `NOTIFY_INDICATE_ENC`）
- **握手**：主机订阅 0xFFE3（CCCD）→ 设备立即发一次 `hello`
- **心跳**：之后每 **10s** 发一次 `hb`（esp_timer 周期）
- 负载：`{"v":1,"evt":"hello|hb","name":...,"uptime_s":...,"batt":...,"chg":0|1,"wifi":0|1,"ip":...}`

## 真机验证（Windows WinRT 客户端）
```
HANDSHAKE: {"v":1,"evt":"hello","name":"ESP32-Buddy-21D2","uptime_s":88,"batt":100,"chg":1,"wifi":1,"ip":"192.168.31.139"}
HB#1/2/3: {"v":1,"evt":"hb",...}   ← 每 10s
```
设备端句柄日志：`ble: handles rx/tx/status=16/18/21`（3 特征均注册）

## 主机侧
- `host/ble_bridge.py` 同时订阅 0xFFE2（控制）与 0xFFE3（状态）→ 日志 `ble handshake OK` / `ble hb#N`
- 桥仍默认不挂守护（BLE 同连占 50% 射频拖慢 ASR）

## 踩坑
- Windows 会缓存已配对设备的 GATT 表：新增特征后需**删除配对 + 设备 BT: PAIR + 重新配对**才能发现（或使用 UNCACHED 模式；本机 UNCACHED 报 device not recognized）
