## 设计（新版）

```
开机 ──读 NVS(petnet/ssid,pass)──►
   无凭据 ──────────────► 配网模式：APSTA（AP 热点 + STA 仅供扫描）+ :80 配置页（自动列出网络）+ :53 DNS 劫持
   有凭据 ──► STA 连接（断线 0/10/20/30/40 s 退避重连）
                 │ 连续 5 个连接周期（≈2 min）无 IP
                 ▼
              回落配网热点（日志 net: sta failed, entering provisioning）→ 用户网页改密码
拿到 IP ──► SNTP（cn.pool.ntp.org / pool.ntp.org，TZ=CST-8）→ pet_engine_set_hour24 + 每小时重推
```

状态机在 `pet-net` 任务内（`idle/sta/ap` 三态），WiFi/HTTP/DNS 全部由任务与各自服务承载，**不阻塞显示/按键/宠物**；任何失败只记日志降级。

## 配网页端点（仅配网热点存活时可达，http://192.168.4.1）

| 端点 | 方法 | 行为 |
| --- | --- | --- |
| `/` | GET | 中文配置页：加载即自动 `fetch('/scan')` 渲染**可点选的网络列表**（名称 + 信号格 ▂▄▆█，按 RSSI > -55 / > -67 / > -78 分档）→ 点选行高亮；**重新扫描**按钮可重扫；密码框 + 保存并连接；折叠的**手动输入（隐藏网络）**兜底（手填即取消列表选中、提交时优先）。内联样式/脚本，无外部资源；页面同时拉取 `/status` 显示当前状态（未配置 / 已保存，正在连接 / 已连接 IP / 时间同步）。默认流程**无需手输 SSID** |
| `/scan` | GET | APSTA 下 `esp_wifi_scan_start`（阻塞式，`wifi_scan_config_t` 默认信道集 + 默认 active dwell，≈2–3 s，< 6 s 处理上限）→ `esp_wifi_scan_get_ap_records` → JSON 数组（RSSI 降序、同名 SSID 去重留最强、跳过空/隐藏 SSID、上限 20 条）：`[{"ssid":"Xiaomi_F7A5","rssi":-42,"auth":3},…]`；`auth` = `wifi_auth_mode_t` 原值（0=开放 … 3=WPA2）；SSID 经 JSON 转义（引号/反斜杠/控制字符）；扫描失败/超时/正忙 → `[]` + **200**（页面提示"未扫描到网络，可重试或手动输入"） |
| `/status` | GET | JSON `{"state":"ap|sta|idle","ssid":"…","ip":"…","hour":-1}`；**绝不含口令**；hour 未同步为 -1 |
| `/save` | POST | `application/x-www-form-urlencoded`（`ssid` 来自列表选中或手动输入 + `password`）；解析 + URL 解码（`+`→空格、`%XX`）；校验 ssid 1..32 字节、pass 0..64 字节；合法：先回"已保存，正在连接家庭 WiFi，可断开热点"页，再交 `pet_net_apply_credentials()`（存 NVS → 状态机 1.5 s 宽限后停热点连 STA）；非法：**400** + 错误页。**口令绝不入日志**。语义与扫描列表版之前完全一致 |

DNS 劫持：UDP :53 收到任意查询（非应答、QDCOUNT≥1）→ 回一条 A 记录 192.168.4.1（TTL 60 s），手机连上热点后自动弹配网页。

热点规格：SSID `ESP32-Buddy-XXXX`（XXXX = softAP MAC 末 2 字节大写十六进制）、开放无口令、信道 1、最多 4 连接、AP IP 192.168.4.1（显式设置）。

## APSTA 与边扫边连

- 配网期间 `esp_wifi_set_mode(WIFI_MODE_APSTA)`：AP 照常广播 `ESP32-Buddy-XXXX` 并服务手机；STA 接口**无凭据、只扫描不连接**，`WIFI_STORAGE_RAM` 下零配置不会自发重连。
- `/scan` 阻塞扫描时 radio 短暂跳到各信道驻留：已关联手机**不断线**（AP 信标照发），但个别信道驻留期间可能有瞬时延迟/抖动——这是"边扫边连"的固有代价。
- esp_http_server 为单线程顺序处理：`/scan` 扫描期间（≈2–3 s）页面同发的 `/status` 等请求会排队到扫描结束后处理，手机端表现只是状态文字稍晚上屏。
- 退出配网仍由 `pet_prov_stop`（httpd_stop → DNS 退出 → `esp_wifi_stop`）→ `net_bring_up` 切回 `WIFI_MODE_STA`，切换路径不变。

| 命令 | 效果 | 日志 |

## NVS / 凭据安全

- namespace `petnet`；键 `ssid`（≤32 字节）、`pass`（≤64 字节），`nvs_set_str` + commit。
- `esp_wifi_set_storage(WIFI_STORAGE_RAM)`：esp_wifi 默认 flash 存储不落凭据。
- 口令只在内存传递（/save → apply → wifi config），代码、日志、/status、串口均不回显。

1. **编译/刷机**：`idf.py build` 通过（app `0x116fa0`，46% 余量）；刷机 + hash 校验通过。

## 边界与不变量

- 无凭据/配网/断网时，显示、宠物、按键行为与此前完全一致（net 失败只降级，不阻塞不崩）。
- 未触碰 host 侧模块（pet_state/render/link/pomo/leisure）、tests、contracts；`pet_rx` 路由与 `wifi.status`/`wifi.provision`/`wifi.clear` 命令不变。
- 热点/HTTP/DNS 任务停止顺序：httpd_stop → DNS 任务退出（≤500 ms）→ `esp_wifi_stop`，之后才切 STA，避免半拆状态。
- 模式共存：STA 阶段仅 `WIFI_MODE_STA`；**配网阶段 APSTA 共存**（AP 服务手机 + STA 仅供扫描、无凭据不连接），两态切换仍由 pet-net 任务单线串行，无锁。
