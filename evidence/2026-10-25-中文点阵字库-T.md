## 2. 覆盖与尺寸

- 覆盖：ASCII 0x20..0x7E（95）+ **GB2312 一级汉字（B0..D7 区，实测 3755 字全部解码）**
  + 常用中文标点 `，。！？：；、（）《》…`（12）= **3862 字**。
- 尺寸：索引 `uint32_t[3862]` = 15,448 B + 位图 `uint8_t[3862][32]` = 123,584 B
  = **139,032 B（≈135.8 KiB）≤ 150 KB 目标**。`cjk16.h` 源文件 879,338 B（数据编译进 .rodata/flash，源文件体积不进固件）。
- 位图：行主序 16 行 × 2 B/行，**MSB = 最左列**；索引严格升序（二分前提，测试断言）。
- 光栅化：**变量字重 560**（Medium/SemiBold 之间，为 16px 无 hint 可读性选定）、
  4× 超采样（54px 渲染）、**50% 块覆盖率阈值**；字集全体字形 ink 包络等比映射到
  16×16 格并居中 → 各字形共享基线（标点沉底、ASCII 居左半格）。
  选型实验：正文字重(400)下笔画约占超采样块面积一半，50% 阈值会随机丢笔画
  （实测「中」丢竖笔）；加重字重 + 50% 阈值出整笔画且密集字（警/鹳）分离最好。
- 抽查：无意外空白字形（除空格）；「中/一/的/餐/，/。/…/A/?」等均在。

## 3. 渲染器 API（pet_text.h/c，纯函数无外部状态）

- `const uint8_t *pet_font16_glyph(uint32_t cp)`：二分查表，缺失返回 NULL。
- `int pet_text_draw16(s, x, y, utf8, max_cells, color, scale)`：UTF-8 逐码点解码
  （1–3 字节画格；**4 字节跳过不占格**；非法序列吞续字节画 '?'）；每码点占 1 格
  （16×scale px，ASCII 同占整格）；scale 1/2；越界逐像素裁剪；返回格数。
- `int pet_text_draw16_wrap(s, x, y, utf8, cells_per_line, max_lines, line_h, color, scale)`：
  按格折行；超容量 `cap = cells/行 × 行数` 时截到 cap−1 格并在下一空格画 `…`；
  返回使用行数（空串 0）。折行按码点，无中英混排断字问题。
- 既有 8×8 `pet_text_draw` API 与其余视图未动。

## 4. 版面决策（pet_engine.c draw_voice_overlay 重排）

- **位置**：宠物下方卡区。清屏区 x 4..130、y 156..233（先填 `PET_SCENE_BG` 再画字，
  彻底盖住下层任务卡避免叠字）；文本原点 (6,160)；**7 格/行 × 4 行**（y=160/178/196/214，
  行距 18px）→ 28 格；宠物区 y≤151，永不重叠。
- **字号选 scale=1（16px）而非 scale=2（32px）**：可用宽 123px 下 32px 仅 3 格/行
  （123/32=3.8）× 4 行 = 12 字 < 常见转写（PTT 文本上限 48B ≈ 16 个汉字），
  且 `REC 999s`/`ASR...` 标签都放不下；16px 达成 ≥6 字/行（7 字）+ 4 行 = 28 格，
  可读性由加重字重（wght 560）补偿。**评估结论：选 16px/7 格。**
- 标签：`REC <s>s` / `ASR...` / `ERR` 红色同区同字号（16px）；转写白色；空转写画 `OK`。
- 行为变化（有意）：浮层从顶部 y≈0 黑条改为下方卡区，不再遮挡顶部状态/宠物；
  番茄钟模式 PTT 活动期间会临时盖住底部 IP 行（瞬时浮层，回到 IDLE 即恢复）。
