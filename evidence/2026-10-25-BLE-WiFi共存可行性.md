# BLE + WiFi 共存通讯方案 · 可行性研究

> 日期：2026-10-25　·　硬件：M5StickS3（ESP32-S3）　·　IDF v5.5.4
> 结论：**有条件可行**。推荐 **WiFi 为主 + BLE 仅在 WiFi 不可用时作为近场备用**，不建议把主链路换成 BLE。

## 1. 硬件/框架事实（本地核实）
- `SOC_BT_SUPPORTED=1`、`SOC_BLE_SUPPORTED=1`（ESP32-S3 支持 BLE 5.0）。
- 当前固件 `CONFIG_BT_ENABLED` **未开**；`CONFIG_ESP_COEX_ENABLED=y`（共存框架已编入）。
- 启用 BT 后 `CONFIG_ESP_COEX_SW_COEXIST_ENABLE` 默认 `=y`（软件时分共存，依赖 `ESP_WIFI_ENABLED && BT_ENABLED`）。
- 资源：app 1.32 MB / 2 MB 分区（**余 ~776 KB**）；PSRAM 空闲 ~8.5 MB。
- 参考项目 `esp32-s3-m5` 在**同硬件**上跑通 **BLE PTT**（NimBLE + S3P 协议 + Windows GATT 客户端），但该项目**没有 WiFi**；"BLE+WiFi 同开"在本硬件**无现成证据**。

## 2. 方案对比
| 方案 | 描述 | 结论 |
| --- | --- | --- |
| **A. WiFi-only（现状）** | 事件 TCP :8766 + ASR HTTPS + NTP；USB 双通道 | ✅ 已跑通，**推荐主力** |
| B. BLE-only（参考项目） | BLE 事件/语音到 PC；无 WiFi | ❌ ASR/NTP 仍需 WiFi，不完整 |
| **C1. WiFi 主 + BLE 近场备用** | WiFi 未连时开 BLE 外设（参考 S3P 协议），手机/PC 直连发事件 | 🟡 有条件可行，**推荐增量** |
| C2. BLE 配网/控制 | 用 BLE 替代 AP 热点配网 | 🟡 需手机 App，收益有限 |
| C3. BLE 低功耗 + WiFi 按需 | 常态 BLE，ASR/NTP 时开 WiFi | 🟡 省电但切换/共存复杂 |

## 3. 成本与风险
- **Flash**：NimBLE（controller+host）+ 协议 ≈ **+150–250 KB**（776 KB 余量够）。
- **RAM**：≈ +30–60 KB（可用 `BT_NIMBLE_MEM_ALLOC_MODE_EXTERNAL` 放 PSRAM）。
- **共存**：单 2.4 GHz 射频时分；BLE notify ~200 B/60 ms 与 WiFi TCP/HTTPS 并发时**吞吐/时延会互相让路**，需实测（ESP-IDF 共存文档明确 heavy traffic 场景建议 SW 共存）。
- **主机复杂度**：Windows BLE 需 WinRT GATT 客户端 + 配对（参考项目已实现，可复用）。
- **功耗**：BLE 广播/连接 + WiFi STA 叠加，**不承诺续航**（250 mAh）。
- **前三风险**：① 共存干扰导致 BLE 丢包/延迟；② Windows BLE 栈与配对 UX；③ 双栈调试与功耗。

## 4. 建议落地路径（若要做）
1. 启用 `CONFIG_BT_ENABLED=y` + `CONFIG_BT_NIMBLE_ENABLED=y`，先只做 **BLE 外设广播**，验证与 WiFi STA 共存（ping/TCP 吞吐对比）。
2. 复用参考项目的 S3P 协议（UUID/MTU/notify 已成熟），**仅在 WiFi 未连接时**开启 BLE（避免常态共存）。
3. 主机侧用 WinRT GATT 客户端（可移植参考实现）。
4. 若共存实测吞吐下降可接受（事件 1 行/秒 + PTT 语音 24 kbps），再考虑 C3。

## 5. 不承诺
- 未实测 BLE+WiFi 同开的吞吐/时延/功耗；未验证 Windows BLE 配对稳定性。
