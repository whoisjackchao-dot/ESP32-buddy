# evidence/实机刷机 —— M5StickS3 真机烧录与运行（H 类）

> 日期：**2026-10-17**；类别：**H（真实硬件）**；关联：`M1`（一帧）/`M3`（版式+卡）/`M5`（音频）；缺口 `B14`（刷写阻塞）/`B15`（环境）
> 结论范围：**已实测**——固件在**真实** StickS3 上烧录成功、启动、外设初始化、心跳稳定。
> **未做** 屏幕**目视**确认与声音**听感**确认（需人工），故各节点 H **只算部分**。

## 0. 背景与两项前置解除

- 本机 = Windows 主机上的 WSL2；设备连在 **Windows 侧 COM5**（`VID_303A&PID_1001`，MAC `70:04:1d:d6:21:d0`）。
- **发现 Windows 侧已有 ESP-IDF v5.5.4**：`D:\Espressif\frameworks\esp-idf-v5.5.4`（python env `idf5.5_py3.14_env`）→ **解除 `B15` 的"无 ESP-IDF"**（Linux/WSL 侧仍无）。
- 首次 `export.ps1` 失败：venv 内 `esptool 4.12.dev2` 不满足约束 `esptool~=4.12`；`pip install "esptool~=4.12"` → **4.12.0** 后通过。
- **`B14`（WSL 直通被组策略挡）以"改在 Windows 侧刷"解决**（即 `B14` 的备选②）。

## 1. 构建（Windows 侧 ESP-IDF v5.5.4）

- 把 `firmware/` 拷到 `D:\buddy_flash\firmware`（规避 UNC 路径构建问题）。
- `idf.py set-target esp32s3 && idf.py build` → **成功**。

| 产物 | 大小（字节） | sha256 |

| `bootloader.bin` | 20,832 | `b7e764457f53ca42bf53e40b487aa98df97f856c4730507eaeb394e6a4360e57` |
| `partition-table.bin` | 3,072 | `7f00b6c042a89b15b0cac534f82ed988caf29278ff5700b0c511eb1b5bb7c820` |

> `esp32_buddy.bin` 491,808 B（分区 1 MB，余 **53%**），与 `evidence/M5/2026-10-16-设备播放-D.md` 的口径一致。
> 偏移：boot `0x0` / 分区表 `0x8000` / app `0x10000`（取自 `flasher_args.json`，与 `flash/MANIFEST.txt` 一致）。

## 2. 烧录（Windows esptool）

```powershell
python -m esptool --chip esp32s3 --port COM5 -b 460800 `
  --before default_reset --after hard_reset write_flash `
  --flash_mode dio --flash_size 8MB --flash_freq 80m `
  0x0 bootloader.bin 0x8000 partition-table.bin 0x10000 esp32_buddy.bin
```

结果：三镜像写入，均 **`Hash of data verified.`**；结束 `Hard resetting via RTS pin...`。

## 3b. 人工目视确认（用户回报，2026-10-17）

> 由**用户观察设备屏幕**（非串口），是 M1 的真实 H 观察点。

- **开机**：屏幕出现**蓝色机器人**（宠物一帧）——**M1 观察点通过**，无异常。
- **随后约 15 s**：转为**灰色**（`OFFLINE`）——因**无任何事件源**（传输未接），`pet_state` 按 `PET_LINK_TIMEOUT_MS=15s` 判失联并**灰化** → `LINK-01`/`OFFLINE` 行为**真机符合设计**。
- **声音**：无（未触发播报，见 §5）。

**解读**：灰化是**预期行为**，不是故障；正说明"失联灰化"在真机生效。要看蓝色 `IDLE` 及其余 6 态，需 **M4 增量 2b 的传输**把事件喂给设备。

## 7b. 剩余 H 的处置（用户决定，2026-10-17）

剩余 H（**其余 4 态 / 任务卡 / 声音 / 刷新率**）**不做临时诊断固件**；**等 `M4` 增量 2b 的传输**接好后，用**真事件**驱动设备再验。

> 理由：避免用"假事件/自造信号"充数，符合 `M4` 契约"**不算完成：只用 curl 假事件、未接真实 OpenCode**"的纪律；也让 H 观察与真实用例（`E2E-01`）一致。
