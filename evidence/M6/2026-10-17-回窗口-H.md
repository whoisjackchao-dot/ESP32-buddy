# evidence/M6 —— 回窗口（B08）· 真机端到端（H 类）

> 日期：**2026-10-17**；类别：**H（真机端到端）**；关联 `R18`/`BTN-05`、`Q15`、`B08`、`M6 §8`
> 结论范围：**已实测**——`KEY1` 短按（值班）→ 设备发控制线 → 主机守护进程 → **OpenCode 终端窗口被带到前台**（用户确认）。

## 0. 装置

- 固件：M6 增量 2（`pet_engine_request_back_window()` 经 USB-Serial-JTAG 写 `{"v":1,"cmd":"back_window"}`）。
- 主机：`host/pet_daemon.py`（读 COM5）+ `host/pet_devio.py`（解析）+ `host/win_focus.py`（窗口激活）。
- 设备 MAC `70:04:1d:d6:21:d0`；目标窗口类 `CASCADIA_HOSTING_WINDOW_CLASS`、标题 `OC | …`。

## 1. 客观证据

- 守护日志（`daemon.err`）反复出现 `[pet_daemon] back_window -> focus ...` → **设备控制线到达并被解析**。
- 窗口激活（改进后）：对目标窗口先 `ShowWindow(SW_MINIMIZE)` 再激活，**5/5 成功**（`focus -> True`，`GetForegroundWindow()==hwnd`）。

## 2. 人工确认

用户在"先点别的窗口让终端失焦、再按 KEY1"后确认：**“可以了”**（终端跳回前台）。

## 3. 过程中发现并修正的 4 个真缺陷

| # | 缺陷 | 影响 | 修正 |
| --- | --- | --- | --- |
| 1 | `host/pet_daemon.py` **缺 `if __name__ == "__main__"`** | 直接运行脚本**什么都不做**（立即退出） | 补 `sys.exit(main())` |
| 2 | `host/win_focus.py` **缺 `import time`** | `time.sleep` 抛 `NameError`，被 `except` 吞掉 → **恒 False** | 补 import |
| 3 | `ctypes.wintypes.WNDENUMPROC` 在 **Python 3.14 不存在** | 设置 argtypes 抛 `AttributeError`，被吞 → **恒 False** | 本地定义 `WINFUNCTYPE` + 在 `_find_target_hwnd` 内设 argtypes；**异常改为打印**不再静默 |
| 4 | 后台进程激活不稳（前台锁） | 失焦/最小化时 `SetForegroundWindow` 被拒 | 加 **ALT 解锁**（`keybd_event(VK_MENU)` 按下+抬起）后重试；最小化场景 **5/5** |

> 其中 #2/#3 被"`except Exception: return False`"掩盖，是本轮耗时的主因——**已改为不静默吞异常**。

## 4. 证据分级

| 结论 | 分级 |
| --- | --- |
| 设备→主机控制线（KEY1 → `back_window` 行） | **本次实测** |
| 守护进程解析 + 分派 | **本次实测** |
| 窗口激活（失焦/最小化 → 前台） | **本次实测 5/5** |

## 5. 残余风险 / 边界

| 项 | 说明 |
| --- | --- |
| 守护进程需常驻 | **主机必须运行 `pet_daemon.py`**（占用 COM5；用前需停掉其他串口程序） |
| 目标识别 | 仅 `CASCADIA_HOSTING_WINDOW_CLASS` + 标题以 `OC` 开头；多终端/改标题会失配（`B08` 不承诺任意窗口） |
| 无鉴权 | 本机 USB 口；守护无 token |
| 菜单 | 仍未实现（`KEY2` 长按只记日志） |
| Windows 专用 | `win_focus` 仅 Windows；Linux 返回 False |

## 6. 复现

```powershell
# 1) 刷 flash/ 固件
# 2) 启动守护（占用 COM5）
python host\pet_daemon.py --port COM5
# 3) 点别的窗口使终端失焦 → 短按 KEY1（值班模式）→ 终端回到前台
```
