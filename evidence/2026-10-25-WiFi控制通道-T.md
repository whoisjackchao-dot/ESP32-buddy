# WiFi 控制通道：设备 → 主机（T）

> 日期：2026-10-25　·　范围：固件（pet_net / pet_engine）+ host（file_to_serial / oc_poll）
> 依据：T 任务「Add a WiFi control channel (device → host) so the voice transcript
> reaches OpenCode even when USB is unplugged」

## 1. 问题（已确认）

- `pet_engine_send_line` 只写 USB-Serial-JTAG；`voice.text`（语音转写）与 `send`
  （KEY1 回车）两条控制线在拔掉 USB（纯 WiFi 场景）时无路可达主机 → 文本推不进 OpenCode。
- host→device 事件通道（TCP :8766）早已双路（M13）；缺的只有 device→host 反向控制路径。

## 2. 设计与端点/命令契约

### 命令（host → device，走既有事件通道 :8766，NDJSON 单行）

```json
{"version":1,"cmd":"host.addr","host":"192.168.31.89","port":8767}
```

- 设备侧 `pet_net_handle_line` 新分支：host ≤63 字节、port 1..65535，非法整条拒；
  存 NVS **namespace `pethost`**（键 `host`=str、`port`=u32），开机 `ctl_start()` 时加载并打
  `net: host addr=<ip>:<port>`（ASCII）。

### 控制行（device → host，WiFi TCP :8767，每行一条连接）

- 新 API `pet_net_send_control_line(line)`：只拷贝入队（深度 **4**、行 ≤**256** 字节，行尾
  `\n` 剥离后发送侧统一补发）即返回 —— 引擎 7fps 循环**零阻塞**；队列满/超长 → 限频（2 s）
  日志丢弃。
- 发送任务 `pet-ctl`（4096 栈，优先级 3）：主机已配置且 STA 已连（`NET_ST_STA` + 有 IP）才发；
  非阻塞 connect + select（**300 ms** 预算）→ SO_SNDTIMEO 500 ms 写 `line\n` → close。
  失败只限频日志，绝不崩。未配置主机/无 WiFi 静默丢（USB 仍在）。
- `pet_engine_send_line`：USB 照旧 **且** 追加 WiFi 镜像（双路并行，主机去重）。

### host 侧

- `file_to_serial.py`：启动探测 Windows LAN IPv4（UDP connect 8.8.8.8:80 取 getsockname，
  不发包；失败且 Windows 才回落解析 `ipconfig`）→ 原子写 `<log>.hostaddr`（tmp+rename）；
  非 Windows 探测失败优雅跳过。另开 `0.0.0.0:<--control-port>`（默认 **8767**）监听线程，
  每行走与 console reader 相同的 handlers（`voice.text` → 剪贴板+Ctrl+V，`send` → 焦点+回车，
  尊重 `--no-voice`/`--no-auto-paste`）。
- **去重**：`LineDedup`（500 ms 窗口）实例由 `main()` 创建，**同时**挂到 USB console reader
  （新参 `line_filter`）与 WiFi 监听器 —— 两条路投递的同一行 500 ms 内只执行一次；不同行
  互不影响；IP 发现（`net: wifi connected ip=`）在 filter 之前，不受影响。
- `oc_poll.py`：`DualSink` 新增 `--control-port`（默认 8767）；每个事件（心跳 5 s 一拍）驱动
  `maybe_announce_hostaddr()`：≥10 s 一次（首次立即）向既有事件 target（`--tcp auto` +
  ip-file 同源）发 `host.addr`；`<out>.hostaddr` 缺失/无 IP 静默跳过，发送失败并入既有限频告警。
- supervisor 不需要改：两个子进程默认值即为 8767。CMake 不变（逻辑都在 pet_net.c）。

## 4. 未验证（诚实边界）

- **编译/烧录**：ESP-IDF v5.5.4 在 Windows 侧，本机不可构建；pet_net.c/pet_engine.c 改动
  仅经静态走查（include、类型、lwip API 签名 `lwip_fcntl/lwip_select/inet_aton`、volatile
  读写位序）确认，未过真实 `idf.py build`。
- **真实 WiFi 控制路径**：设备 → 8767 的端到端（connect 预算、SO_SNDTIMEO、NVS 断电保留）
  未上真机；`host.addr` 依赖主机 IP 变化后 10 s 内重公告 + 设备 NVS 新值，真机时序未测。
- **USB+WiFi 双路去重（实测）**：单机去重逻辑有 loopback 实证；真机双路毫秒级到达的实测
  未做（依赖烧录）。
- **行上限 256 B 的取舍**：超长 voice.text 行（约 >200 汉字转写，理论最长 ~1.1 KB）在 WiFi
  路径整行丢弃（限频日志），USB 路径不受影响 —— 按任务设计「行 ≤256 字节」执行；
  若纯 WiFi 场景需要长转写，后续可将 CTL_LINE_MAX 提到 PET_LINE_MAX(512) 或分帧。

## 5. 使用

```bash
# 固件烧录后（无新配置项；host.addr 由 host 侧自动下发）
# Windows 桥（默认即开 8767 监听 + 写 <log>.hostaddr）：
python.exe file_to_serial.py --log D:\buddy_flash\oc_events.log [--control-port 8767] [--no-voice] [--no-auto-paste]
# WSL poller（默认每 ~10 s 向设备公告 host.addr）：
python3 host/oc_poll.py --out /mnt/d/buddy_flash/oc_events.log --tcp auto [--control-port 8767]
# 验证：拔 USB → 按住 KEY1 说话 → 转写经 WiFi 到 8767 → 剪贴板+Ctrl+V；KEY1 短按 → 回车
```
