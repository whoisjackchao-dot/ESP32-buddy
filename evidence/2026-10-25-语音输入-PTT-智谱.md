# 2026-10-25 语音输入 PTT（按住 KEY1 说话 → 智谱 ASR → 转写回屏 + 上报主机）

状态：**代码完成（inspection 级），未构建/未刷机/未实测**（本机无 IDF 工具链；
IDF v5.5.4 构建环境在 Windows `D:\buddy_flash`）。

## 1. 设计与流程

```
KEY1 按下沿(PRESS) ──▶ pet_engine_key ──▶ pet_ptt_on_key(true)
   （菜单打开时不转发；不进键表）
   ▶ 状态=RECORDING；pet-ptt 任务被唤醒：
     PSRAM 分配 44+960000B（30s 顶格；不足降 44+320000B=10s；再不足→ERROR）
     循环：pet_audio_mic_read(960 样本=60ms) → 追加到 44B 头之后
     停止条件：松键(s_stop_req) / 时长硬顶(30s 或 10s) / 缓冲满
KEY1 松开沿(RELEASE) ──▶ pet_ptt_on_key(false) ──▶ s_stop_req=true
   ▶ 录音 <300ms → 丢弃（IDLE，log "voice: too short"）
   ▶ 否则 填 WAV 头 → 状态=UPLOADING → HTTPS POST 智谱 ASR
     200 且 JSON 有 "text" → DONE（屏显文本 ~5s）
       + log "voice: text=<...>"
       + 控制线 {"v":1,"cmd":"voice.text","text":"<escaped>"} → USB 主机
     其他 → ERROR（log "voice: asr failed <code>"）
   ▶ 缓冲立即释放（free）；DONE/ERROR 满 5s 懒回收回 IDLE
```

- 录音+上传全部在独立任务 `pet-ptt`（栈 12288B，TLS 握手峰值在此任务，待实机核）。
  按键/动画/引擎/rx 任务全程不阻塞。
- 事件/错误只置状态与日志，绝不崩溃、绝不 assert。

## 2. 引脚与音频参数（与参考实机 StickS3 @3864d7fb 一致）

| 项 | 值 | 出处 |
| --- | --- | --- |
| I2C | SDA=47 / SCL=48（pet_hal_sticks3 已装，本增量不动） | 参考实机 |
| I2S | MCLK=18 / BCLK=17 / WS=15 / **DIN=16** / DOUT=14 | 参考实机 |
| ES8311 | 0x18（备选 0x19）；16-bit；16kHz；MCLK×256 | 参考实机 |
| 槽位 | **STEREO**（MONO 会 2 倍拉伸）；读立体声取左声道 | 参考实机 |
| 麦配置 | `es8311_microphone_config(codec,false)` + `ES8311_MIC_GAIN_24DB`，首次 `pet_audio_mic_enable(true)` 时配置一次 | 参考实机 |
| 供电 | L3B（PM1 GPIO2）已由 `pet_hal_sticks3` 上电；`pm1_es8311()` 是功放不是 codec 电源 | 既有代码 |
| RX 使能 | `pet_audio_init` 即 init+enable RX（全双工同通道 I2S_NUM_0，TX 配置不变） | 参考实机同款 |

`pet_audio` 新 API：`pet_audio_mic_read(mono, samples≤960, timeout_ms)`（内部读
STEREO 取左），`pet_audio_mic_enable(bool)`（幂等；false 关 RX DMA）。播放路径
（TX/静音尾/功放开关）零改动，仅 std_cfg 的 din 从 UNUSED 改为 GPIO16。

## 3. 缓冲与帧

- PSRAM `heap_caps_malloc(44 + 30*16000*2, MALLOC_CAP_SPIRAM)` = 960044B；
  不足则 44+320000B（10s）；WAV 头常驻缓冲前 44B，PCM 顺序追加，上传时
  `Content-Length = strlen(PART1) + 44 + pcm + strlen(TAIL)`，**流式分块写**（4KB/块），
  不再复制大缓冲。
- 帧：960 样本 = 60ms @16kHz；30s 硬顶到时视同松键并继续走上传。
- 上传/结束即 `free`；IDLE 态无常驻大缓冲。

## 4. 端点与 multipart（智谱 GLM-ASR）

- `POST https://open.bigmodel.cn/api/paas/v4/audio/transcriptions`
- Header：`Authorization: Bearer <key>`、`Content-Type: multipart/form-data; boundary=petptt-b7f31c9a`
- 字段顺序：`model=glm-asr-2512`、`stream=false`、`file`（filename=`audio.wav`，
  Content-Type `audio/wav`，内容 = 44B WAV 头 + 16kHz/mono/16bit PCM）
- 证书校验：`crt_bundle_attach = esp_crt_bundle_attach`（IDF 5.5 默认组件；
  `sdkconfig.defaults` 显式加 `CONFIG_MBEDTLS_CERTIFICATE_BUNDLE=y`）
- 响应 200 → 取 `"text"` 字符串（极小提取器，移植参考实机 `asr_adapter.c`：
  支持 `\" \\ \/ \b\f\n\r\t` 与 `\uXXXX` 含代理对 → UTF-8）。响应体截断到 1KB。
- 状态码：401/5xx/传输错误均归 `voice: asr failed <code>`。

## 5. 按键与映射变化

- `pet_button`：新增 `PET_KEY_EV_PRESS`（按下沿）/`PET_KEY_EV_RELEASE`（松开沿）。
  松键沿同时判出 SHORT 时，RELEASE 进 3 深事件 FIFO 排在 SHORT 之后按序发出；
  病态持续抖动积满队列时丢最旧（保 PTT 启停沿）。SHORT/LONG 语义与去抖不变。
- `pet_keymap`：值班 KEY1 **长按 → PET_ACT_NONE**（静音收敛到菜单 MUTE 项）；
  PRESS/RELEASE 不进键表（引擎直通）。`PET_ACT_MUTE_TOGGLE` 枚举保留不产。
- `pet_engine_key`：PRESS/RELEASE 仅在 KEY1 且菜单关闭时转发 `pet_ptt_on_key`，
  其余（KEY2、菜单中）一律吞掉。菜单 SHORT/LONG、番茄钟、回窗口、配网全不动。
- 已知交互（按规格保留）：值班 KEY1 快速轻点 = PRESS→PTT（<300ms 丢弃）+ SHORT→
  回窗口照发。

## 6. ASR key 供给（serial cmd 路由，绝不入日志）

走既有 `pet_rx.apply_line → pet_net_handle_line` 的 `"cmd"` 通道（USB 与 WiFi :8766
同路）：

| cmd | 行为 |
| --- | --- |
| `{"version":1,"cmd":"asr.set","key":"..."}` | 存 NVS namespace `petasr` key `key` + 内存副本；log 仅 `asr: key set` |
| `{"cmd":"asr.status"}` | log `asr: key set|missing` |
| `{"cmd":"asr.clear"}` | erase；log `asr: key cleared` |

key 只出现在 NVS/内存/HTTP 头；日志与回显永不包含。

## 7. 显示与主机上报

- `draw_voice_overlay`（pet_engine，画在值班/番茄钟整屏之上、菜单屏不画）：
  `REC <s>s`（红）/ `ASR...`（红）/ 文本（白，8×8 字库 16 字×3 行硬折行，超出末行
  补 `...`；非 ASCII 折叠为 `?`，屏显上限 ~48 字符格）/ `ERR`（红）。DONE/ERROR
  满 ~5s 自动消失。注意：8×8 字库无汉字字形，中文转写在屏上为空白（`?` 折叠），
  完整文本以日志与控制线为准。
- 控制线：`{"v":1,"cmd":"voice.text","text":"<json-escaped utf8>"}\n`，经新增
  `pet_engine_send_line()`（`back_window` 同一 `usb_serial_jtag_write_bytes` 出口），
  文本转义 `"` `\` `\n` `\r` `\t`，其余控制字节丢弃，UTF-8 原样透传，截断 512B。

## 9. 验证（本机可做的部分）

- `pet_button` 状态机以 1:1 转写（Python）跑了 8 组确定性序列（即
  `tests/test_pet_button.c` 的 b01–b08 全部分支）+ 5000×400 步随机 raw 抖动 fuzz：
  **无事件丢失、无乱序**（干净状态下 0 违例；只有持续病态抖动触发丢最旧后才有
  断口，属设计内降级）。fuzz 在过程中实打实抓出并修掉两个真 bug：
  1-slot pend 的丢事件缺陷 → 改 FIFO；RELEASE 先于 SHORT 入队的排序缺陷 →
  改两段式 emit/push。
- `tests/run.sh`（host T 类）无法在本机跑（无 cc/gcc）；`test_pet_button.c`/
  `test_pet_keymap.c` 已按新语义更新，逻辑与上述转写一致，待 Windows 侧跑绿。
- 其余为逐文件 inspection（见 §10 未验证清单）。
