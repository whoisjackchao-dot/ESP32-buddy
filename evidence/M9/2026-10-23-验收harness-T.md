## 3. harness 口径（实现决定，均有依据）

| # | 口径 | 依据 / 说明 |
| --- | --- | --- |
| 1 | 跨机时延一律 `host send 完成 → host 收到对应日志行`（`time.monotonic()`），设备 `t=<us>` 仅作证据记录 | M9 §1 通用规则 |
| 2 | G3/G6 每次发**互异 8 字符内 title** 的卡片事件，匹配 `since=t_send` 后第一条 `top==title[:8]` 的 `rf`，3 s 超时记 `timeout` 留分母 | M9 §3 G3/G6；`top=%.8s` 截断口径见 `evidence/M9/2026-10-23-设备可观测性-D.md` |
| 3 | G4 “停发”时刻 = **最后一拍心跳 send 返回时刻**；每 1 s 一拍、发 5 s（6 拍）后停；等 `off` 至停发+20 s，delta=off_recv−stop | M9 §3 G4（“停发 → off”）；15 s 判线对应 `PET_LINK_TIMEOUT_MS=15000`（`pet_state.c`） |
| 4 | G7 正例：每次先发 `task.start`（回 WORKING）→ 等 1.5 s → 触发 `agent.input_required`/`task.done`/`task.error`（7/7/6 轮转）→ 观察 1.5 s，窗口内**恰好 1 条正确 id** `voice` | M9 §3 G7；声音映射读 `pet_state.c`（进入 INPUT/DONE/FAILED 才置 `pending_sound`）+ `pet_voice.h`（id 1/2/3） |
| 5 | **G7 对照-idle 特殊处理**：`pet_state.c` 中 `agent.idle` 自 WORKING/INPUT_REQUIRED 进入 1.5 s done 边沿去抖 → **到点转 DONE 并播 done 音**（非静默）。故对照 idle 试验为：回 WORKING → 发 `agent.idle`（等 2.5 s 让边沿音在窗口前放完）→ 再发 `agent.idle`（DONE→IDLE，真静默）→ 观察 1.5 s 计 0 条 | 契约“对照组应静默”只能在该状态序列下对固件成立；否则对照必然录到 +1.5 s 的边沿音（误报）。已在代码注释与本记录双处注明 |
| 6 | 对照-working/heartbeat：回 WORKING 后再发 `task.start`（WORKING→WORKING）/`device.heartbeat`，各观察 1.5 s 计 0 条 | `pet_state.c`：两者均不置 `pending_sound` |
| 7 | G6 轮转 `task.start / agent.input_required / task.done / task.error / agent.blocked`，**不含 heartbeat** | M9 §3 G6“任意事件 1 s 内显示”——heartbeat 不改视图，永远无 `rf`，入轮转只会烧满 3 s 窗口 |
| 8 | 判定字段 `PASS/FAIL`；报告含总尝试/达标/失败/超时 + p50/p95（仅实测样本）+ 逐次行（含 `send/recv monotonic`、原始日志行） | M9 §1/§4（分母完整、逐次记录） |
| 9 | 串口层收敛于 `Link` 接口（`write_line/read_line/close`）；`SerialLink` 惰性 `import serial`；reader 线程解析并盖 `monotonic()` 收时戳；`send()` 写 JSON 行 + `\n` + flush 后记 `t_send` | 任务约束（可注入、WSL 不可及 COM5）；M4 §6.1 帧 |
| 10 | `--dry-run` 由 `DryRunDevice` 按契约语义合成日志（含 15 s 链路超时、1.5 s done 边沿、5 s DONE 驻留、`st:` 1 s 噪声、`%.8s` top 截断），**CLI 全时序自检四闸门**；输出默认落 `evidence/M9/dry-run/` 并在报告标注“非实机证据”，避免污染实证命名空间 | M9 §2/§4；任务“dry-run 自检” |
| 11 | 事件发送前 `validate_event`（M4 §6.1：version==1、7 已知事件、title/project ≤63、elapsed_s 非负整数、整行 ≤512），坏事件**拒发**而不是烧掉试验窗口 | M4 §8.3“不广播”语义的发送侧对应 |

## 6. 残余风险

| 风险 | 说明 |
| --- | --- |
| **串口路径未验证（最大风险）** | 本机无 COM5、未装 pyserial：`SerialLink`（打开端口/`write`+`flush`/`readline` 解码）**零实机行使**。首次真机运行建议先单跑 `--gate g3` 观察 `--out` 报告里的原始 `rf` 证据行是否如预期 |
| **固件未刷写** | M9 §2 可观测性已落地 `pet_engine.c`（见 `2026-10-23-设备可观测性-D.md`，D 类）但**待刷写**；真机数据采集以刷写为前提 |
| Windows 运行时差异 | 在 WSL/Linux 验证；Windows 控制台编码已尽量兜底（文件强制 UTF-8、stdout `reconfigure`），但 Windows pyserial 版本/驱动行为未测 |
| G4 判据字面 | 契约字面“≥19/20 在 15–17 s”允许 19 pass + 1 timeout 判 PASS（timeout 已留分母并单独计数）；若要“≥19/20 且 0 timeout”需改判据，未擅改 |
| G7 对照-idle 依赖状态序列 | 见 §3-5：若固件把“WORKING→idle 边沿音”视为缺陷，应在 `pet_state` 层修，而本对照按“DONE→IDLE 真静默”测量；两者口径已写死在代码注释 |
| 时延含全链路 | delta 含 USB-Serial-JTAG 双向 + 固件渲染排队，非“纯渲染时延”（M9 §1/§5 既定口径）；1000 ms 判线的真实裕量待实机数据 |
| 真机 G4 首拍相位 | 真机若在试验开始前已离线（如 harness 启动前静默 >15 s），第一拍心跳会先触发 `on` 再计时——harness 只认停发后的 `off`，理论自洽，但未实机回归 |
| 人工门槛未实现 | 契约 §4 的 `g1/g2/g5` 子命令不在本任务范围（任务指定 `g3|g4|g6|g7`） |
