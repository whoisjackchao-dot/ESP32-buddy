# ASR「出错了」根因与修复（BLE 引入后）

## 现象
语音识别显示「出错了」，实际链路在设备侧失败。

## 根因（三层，按发现顺序）
1. **设备 IP 变了**（.198 → .139，DHCP 重分配）——排查时用旧 IP 误判"离线"。
2. **DNS 解析失败**：`getaddrinfo() returns 202`（EAI_FAIL）→ 加静态 DNS（223.5.5.5 / 114.114.114.114）+ 开机 DNS 探针（`net: dns probe rc=0 ip=39.106.105.100`）。
3. **内部 RAM 不足**：BLE(NimBLE) 默认用内部 RAM，导致 `mbedtls_ssl_setup -0x7F00`（MBEDTLS_ERR_SSL_ALLOC_FAILED）→ **NimBLE + mbedTLS 改走 PSRAM**（`BT_NIMBLE_MEM_ALLOC_MODE_EXTERNAL` / `MBEDTLS_EXTERNAL_MEM_ALLOC`）。

## 修复后
- 内部堆空闲 **34,695 B**（心跳日志 `int=` 可见）
- DNS 探针 `rc=0`
- 语音识别恢复正常（用户确认）

## 教训
- BLE 引入后必须监控**内部堆**（总堆 8MB 不代表内部够）：心跳加 `int=`。
- 排查设备"离线"先确认当前 IP（ip-file/串口 boot 日志），不要沿用旧 IP。
- 大组件（BT/TLS）优先放 PSRAM。
