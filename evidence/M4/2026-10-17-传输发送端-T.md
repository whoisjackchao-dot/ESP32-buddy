| 用例 | 断言要点 |
| --- | --- |
| `E2E-02` | `ensure_line(str)`：无 `\n` → 补一个；已有 `\n` → 不重复；`\r\n` → 归一为单个 `\n`；多个尾随 `\r\n`/`\n` → 仍只留一个；UTF-8 编码。`ensure_line(dict)`：紧凑 JSON（`separators=(",",":")`）+ `\n`；非 ASCII（`中文`）**原样 UTF-8 直传**，不出现 `\uXXXX`。`ensure_line(123)`/`(["nope"])` → `TypeError` |
| `E2E-02` | `SerialSink(serial_obj=FakeSerial)`：每次发送写入的字节**恰为** `ensure_line(x)`；两次发送 → 恰好追加两行；`close()` 关闭注入串口；**惰性契约**：不带 `serial_obj` 构造 sink 不触发 `import serial`（`sys.modules` 无 `serial`） |
| `E2E-02` | `pet_sender.main([...], open_sink=…)`：合法 JSON 参数 → 返回 **0**，`open_sink` 收到 `("COM7", 9600)`，FakeSerial 恰收到一行 `{"version":1,"event":"task.done","title":"Hello"}\n`，stderr 出现 `sent N bytes` |

另做两次**人工冒烟**（非用例，本机）：
- `python3 host/pet_sender.py --help` → 正常打印用法（`--port` 默认 `COM5`、`--baud` 默认 `115200`），**全程不 import pyserial**；
- `echo '{"version":1,…}' \| python3 host/pet_sender.py --stdin --port /dev/null` → 首次使用时惰性 `import serial` 并尝试打开端口（`/dev/null` 非真串口故 `SerialException`，**恰好证明**惰性 import 与"首用才开"只发生在真实串口路径）。

## 3. 参数（提案值，**待批准**）

| 符号 | 值 | 依据 |
| --- | --- | --- |
| `PET_RX_BAUD` | 115200 | M4 §9.4（USB-CDC 名义值；CDC 忽略 baud） |
| `DEFAULT_PORT`（CLI `--port`） | `COM5` | M4 §9.3（设备已在 COM5，走 USB-Serial-JTAG） |

| 非 JSON / 非对象输入 | stderr 报错、**不发送**该行（§8.3"不广播"语义沿用）；stdin 模式跳过坏行继续、退出码 1；位置参数模式退出码 1 | §9.3 契约留白（CLI 未规定非法输入行为），选与入口核心一致读法 |
| 帧化来源 | CLI 先 `json.loads` 校验为**对象**，再交 `ensure_line(dict)` 紧凑序列化（保证与 §6.1 设备侧可解析形态一致，避免原样透传非紧凑/非法行） | §9.3 + §6.1 |

## 4. 残余风险

| 风险 | 说明 |
| --- | --- |
| **真机串口未验证** | 测试全部用 `FakeSerial` 注入，**不开真实串口**；真机 `COM5`（ESP32 USB-Serial-JTAG）端到端收发待实机验证（H 类待设备） |
| **Windows pyserial 路径未验证** | 真实串口路径（惰性 `import serial` → `serial.Serial(port, baud)`）在本机仅冒烟到"打开失败"，未在 Windows + pyserial + COM5 上验证；`--port` 默认 `COM5` 为 Windows 命名，Linux 下需显式给设备路径 |
| OpenCode 映射未做 | 仍属 §9.5 明确不做（`Q12`/`Q17` 未决）；本发送端只负责"已定 JSON → 设备线 → 串口" |
| 串口打开失败的错误处理 | 真实路径 `SerialException` 直接向上抛（CLI 非零退出）；是否要友好报错/重试未定，契约未规定 |
| 行长上限未在发送端强制 | §9.1 超长丢弃由**设备侧** `pet_rx` 负责；发送端不拦 512 上限（契约未要求主机侧预检） |
| 常量待批准 | 见 §3 表 |
