# evidence/M4 —— USB-Serial-JTAG 传输 · 真机端到端（H 类）

> 日期：**2026-10-17**；类别：**H（真机端到端）**；关联：`R12`/`E2E-02`、`R15`/`AUD-05`、`M2` 6 态、`M3` 卡、`M5` 语音；契约 `M4 §9`
> 结论范围：**已实测**（真机）。**未**覆盖：OpenCode 真源（`R11`）、多卡、刷新率数值。

## 0. 装置

- **固件**：本次构建（含 `pet_rx` + `pet_linebuf`）已刷入 StickS3（`COM5`，MAC `70:04:1d:d6:21:d0`）。
- **主机发送端**：`host/pet_transport.py`/`host/pet_sender.py`（§9.3）＋一个等价循环脚本（`send_demo.py`，同一 `ensure_line` 定帧：§6.1 紧凑 JSON + `\n`、UTF-8），每 6 s 一个事件。

## 1. 客观证据：传输可达 + 非法丢弃（不崩）

发送一行 `not json\n` → **设备日志**：

```
W (4477) pet-rx: link parse err=2（已丢弃）
```

含义：host→device 字节**到达**；`pet_linebuf` 切行 → `pet_link_parse` 返回 `JSON` 错误 → **记 warn、丢弃、不崩**（契约 §9.2）。
附带观测：**打开 COM5 不触发设备复位**（无 boot 日志，心跳继续）。

**提交的发送端 CLI 也在真机跑通**（Windows venv + pyserial）：

```
> pet_sender.py --port COM5 --stdin   # 两行事件由 stdin 喂入
sent 96 bytes
sent 71 bytes
exit=0
```

## 2. 人工观测（用户，2026-10-17）

- **状态依次变化**：`task.start`→工作 / `agent.input_required`→需确认 / `task.done`→做完 / `task.error`→出错。

- **听到语音**：**“需要你确认下 / 做完啦 / 出错了”**（三句，对应 input / done / failed）。
