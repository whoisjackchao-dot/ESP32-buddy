## 设计：双通道统一入队，单消费者改状态

```
USB-Serial-JTAG ──► pet-rx 任务 ──┐
                                  ├──► 行副本队列(16 × ≤512B) ──► pet-rx-apply 唯一消费者
WiFi TCP :8766 ──► pet-evt 任务 ──┘         pet_rx_submit()        │  跨通道去重（500 ms）
                                                                  ▼
                                                    apply_line → pet_link_parse → pet_state
                                                    （"cmd" 行仍先路由 pet_net_handle_line）
```

- **单消费者不变量**：`pet_state` 的全部事件路径变更只发生在 `pet-rx-apply` 一个任务。
  TCP 任务、USB 任务都只调 `pet_rx_submit()`（拷贝入队），不触碰状态。此前
  rx 任务与 engine 任务的读写竞争面没有扩大，反而收敛为单写者。
- **队列**：FreeRTOS queue **按值**存行副本（16 深度 × `size_t + 512+1 字节 ≈ 8.5 KB`，
  `pet_rx_start` 时一次性分配，固定上限）。满即丢 + 限频（2 s）warn `rx: queue full (dropped)`，
  生产者（USB/TCP）永不阻塞。
- **消费任务**：`pet-rx-apply`（栈 4096，优先级 5，与旧 rx 任务同级）——出队、去重、
  `apply_line`。解析失败/超长的处理与 M4 逐字不变。

## 公共 API

| API | 语义 |
| --- | --- |
| `void pet_rx_submit(const char *line, size_t len)`（`pet_rx.h`） | 任意任务上下文提交一行（线程安全；整行拷贝入队）。`len==0 / > PET_LINE_MAX(512)`、队列未就绪或满：丢弃 + 限频日志。 |

## 跨通道去重（USB+WiFi 双投递无害化）

- 在**消费者**内做：与**上一条已应用行**逐字节全等、且距其应用时刻 **< 500 ms** → 丢弃。
- 窗口锚定在"上一条已应用行"的时刻，跳过时不刷新窗口 —— 连续重复行最坏 2 s 一条日志，
  不会把窗口无限推延。
- 命中去重：限频（2 s）warn `rx: dup dropped`（ASCII）。
- 语义边界：同样内容若间隔 ≥500 ms 会应用两次 —— 与单通道旧行为一致（不做更重的
  事件幂等，事件行格式不变）。

## WiFi TCP 事件服务器（新文件 `pet_evt_tcp.c/h`）

- **端点契约**：`tcp://<STA-IP>:8766`，绑定 `0.0.0.0`；**单客户端顺序 accept**
  （宿主机一个 poller 即可；第二个连接排队在 backlog=1，前一个断开后被接走）。
- **帧格式**：NDJSON 与 USB 完全一致（不改事件行格式）；按 `\n` 切行（兼容 CRLF，剥 `\r`，
  复用 host 已测的 `pet_linebuf`），行 ≤ 512 字节，超长整行丢弃（`net: event line too long (dropped)`），
  空行忽略。每行 → `pet_rx_submit()`。
- **生命周期**（在 `pet_net.c` 挂接，`pet_prov.c` 的 AP 流程零改动）：
  - `IP_EVENT_STA_GOT_IP` → `pet_evt_tcp_start()`：首次创建常驻任务 `pet-evt`（栈 4096，
    优先级 4）并使能；已在监听时（如 IP 变更）为幂等空操作。开监听即打一条
    `net: event server tcp://<ip>:8766`。
  - `WIFI_EVENT_STA_DISCONNECTED` / `sta_stop_radio()`（wifi.clear、菜单配网、转热点）→
    `pet_evt_tcp_stop()`：只清使能标志；任务在 ≤0.5 s（accept 轮询）或 ≤2 s（recv 静默超时）
    内自查到后**自行**关套接字，打一条 `net: event server stopped`，回落驻留等待下次 start。
    **绝不在另一任务阻塞于 accept/recv 时跨任务 close**（lwip 下不可靠）。
- **健壮性**：lwip sockets（`lwip/sockets.h`）；`SO_REUSEADDR`；accept/recv 均设
  `SO_RCVTIMEO` 周期自查；`EAGAIN/EWOULDBLOCK/ETIMEDOUT/EINTR` 视为瞬态；其余错误只记
  warn/err 并关套接字重来或回落，不崩。断开时 STA 事件日志、SNTP、显示/按键全部不变，
  **USB 路径全程可用**（无 WiFi 时 USB 走同一队列，逐行语义与 M4 版一致）。
- **客户端断开**：`recv()==0` 或错误 → 关连接、打 `net: event client closed`，回到 accept。

## 运行侧契约（宿主机 poller 视角）

1. 等设备日志 `net: wifi connected ip=<ip>` → `net: event server tcp://<ip>:8766`。
2. `nc <ip> 8766`，逐行发送 NDJSON（每行一个 JSON 事件，`\n` 结尾）。同一行 500 ms 内
   从 USB 与 TCP 各发一次 → 状态只应用一次（`rx: dup dropped` 至多 2 s 一条）。
3. 断开重连即可换连接；STA 断开后端口关闭（`net: event server stopped`），重连拿到 IP 后
   重新可连。USB 串口事件入口全程照旧。

## 边界与不变量

- 无 WiFi 时：`pet-evt` 任务驻留轮询（200 ms 级延时，不占端口），USB 行为与旧版一致。
- 队列内存固定（≈8.5 KB，`pet_rx_start` 一次分配）；任何路径都不阻塞生产者。
- `pet_evt_tcp_start` 只在默认事件循环任务调用（GOT_IP），`s_task_up` 无并发创建风险；
  `stop` 可能来自事件循环或 pet-net 任务，二者只写 `s_enabled`（volatile bool，最坏延迟一个自查周期）。
- AP 配网阶段监听器必为停机态（`sta_stop_radio` 已 stop；GOT_IP 未发生）——:8766 不会与
  `pet_prov` 的 :80/:53 冲突。
