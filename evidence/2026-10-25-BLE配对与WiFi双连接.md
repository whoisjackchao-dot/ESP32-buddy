# BLE 配对 + WiFi 双连接 · 可行性研究

> 日期：2026-10-25　·　硬件：M5StickS3（ESP32-S3，单 2.4 GHz 射频）　·　IDF v5.5.4
> 结论：**可行（官方支持且稳定）——限 WiFi STA 场景**；`WiFi AP + BLE` 官方标记为 **不稳定（C1）**。
> 依据：`esp-idf/docs/en/api-guides/coexist.rst` 支持矩阵 + `components/esp_coex/Kconfig` + `components/bt/host/nimble/Kconfig.in`（本机 IDF v5.5.4）。

## 1. 官方共存支持矩阵（关键行）
| Wi-Fi 状态 | BLE Scan | BLE Advertising | **BLE Connected（配对后）** |
| --- | --- | --- | --- |
| **STA（Scan/Connecting/Connected）** | Y | Y | **Y（稳定）** |
| **SOFTAP（Connecting/Connected）** | C1 | C1 | **C1（支持但不稳定）** |
| Sniffer RX | C1 | C1 | C1 |

- **Y** = 支持且性能稳定；**C1** = 支持但性能不稳定。
- 结论：**BLE 配对连接 + WiFi STA 同时工作 = 官方支持且稳定**；但**配网热点（SOFTAP）+ BLE 同时 = 不稳定**（我们现在的 AP 配网不应与 BLE 并跑）。

## 2. 射频机制（为什么有代价）
- 单 2.4 GHz 射频**时分复用**：Wi-Fi 与 BLE 按时间片交替使用，不能同时收发。
- **Wi-Fi CONNECTED + BLE CONNECTED 的时间片各占 50%**（官方文档）。
- 影响：
  - BLE 连接期间，**Wi-Fi 吞吐≈减半**（ASR 上传 30s WAV ≈1.5 MB 会变慢）；
  - Wi-Fi 事件/控制时延上升（但事件仅 1 行/秒、控制行极小，影响可接受）；
  - BLE 自身吞吐低（~几十 KB/s 量级，够控制/事件，不够音频）。

## 3. 资源成本
- 需启用 `CONFIG_BT_ENABLED=y` + **`CONFIG_BT_NIMBLE_ENABLED=y`**（BLE-only，省内存）；
  启用后 `CONFIG_ESP_COEX_SW_COEXIST_ENABLE` 默认 `=y`（软件共存，重流量推荐）。
- 配对/绑定：`BT_NIMBLE_SECURITY_ENABLE` + `BT_NIMBLE_SM_SC`（LE Secure Connections）+ `BT_NIMBLE_MAX_BONDS`；
  主机侧 Windows 用 WinRT GATT + 配对（参考项目 `esp32-s3-m5` 在同硬件做过 BLE 配对加密，但**未同开 WiFi**）。
- 预估：Flash **+150–250 KB**（当前 app 1.57 MB / 2 MB，余 ~520 KB，够）；RAM **+30–60 KB**（可用 PSRAM 承载 BT 内存）。
- 功耗：BLE 连接 + WiFi STA 叠加，**不承诺续航**（250 mAh 电池）。

## 4. 对本项目的适用性
| 用途 | 是否推荐 | 原因 |
| --- | --- | --- |
| 事件传输（host→device） | 🟡 仅作备用 | WiFi TCP 已稳定；BLE 带宽低、50% 时分 |
| 语音上行（ASR） | ❌ 不推荐 | WiFi HTTPS 更合适；BLE 带宽不足 |
| 控制线（device→host，voice.text/send） | ✅ 可作 WiFi 不可用时的近场兜底 | 行极小，BLE 足够 |
| 配网（手机 App） | 🟡 条件 | **BLE+SOFTAP 不稳定**；需 BLE 与 AP 互斥（先 BLE 配网、再关 BLE 开 STA） |

## 5. 若落地（建议顺序）
1. 启用 NimBLE + 安全/绑定；先只做 **BLE 广播 + 配对**（WiFi 关闭）验证主机配对。
2. 再做 **WiFi STA + BLE 连接**并存，实测：ASR 上传耗时、事件时延、丢包。
3. 控制线兜底策略：**WiFi 优先；STA 断开时才启用/广播 BLE**（避免 50% 时分常态开销）。
4. 配网仍用 AP 热点（BLE 与 SOFTAP 不并跑）。

## 6. 不承诺 / 未验证
- 未实测本应用在 BLE+WiFi 同开下的吞吐/时延/功耗。
- Windows BLE 配对（Just Works/LESC）在 OpenCode 场景的稳定性未验证。
- **AP（SOFTAP）+ BLE 不稳定**是官方结论，不能用于"BLE 配网 + 热点同时"。
