# 双通道事件（T）

> 日期：2026-10-24　·　范围：host 侧（Python），事件双通道：USB 文件桥 + WiFi TCP，USB 自动发现设备 IP
> 依据：T 任务「Extend the ESP32-buddy host tools so events go to the device over WiFi TCP in addition to the existing USB file bridge, with automatic device-IP discovery from the USB console」

## 1. 背景与目标

现状：`oc_poll.py` 把事件写成 NDJSON（FileSink），Windows 桥 `file_to_serial.py` 尾随该文件写 COM5（USB 单通道）。
设备侧（另行交付，本次不动固件）将在 **TCP :8766** 收 NDJSON 行，并在 USB 控制台打印
`net: wifi connected ip=<ip>`。本次让 host 侧同一行事件同时走两条路：文件（USB）+ TCP（WiFi），
IP 由桥进程从控制台自动发现，无需手工配置。

## 3. 双通道设计

```
oc_poll.py (WSL)                                file_to_serial.py (Windows, COM5)
┌──────────────────────────────┐   tail          ┌────────────────────────────────┐
│ DualSink                     │ ──────────────► │ main loop: ser.write(new bytes)│──► USB CDC ──► 设备
│  1. FileSink.write_line(file)│                 │ reader 线程: ser.readline()    │◄── USB CDC ←─ 控制台
│  2. tcp_send(target, line)   │                 │   net: wifi connected ip=<ip>  │
└──────────────┬───────────────┘                 │   → <log>.ip (tmp+rename 原子) │
               └── WiFi TCP :8766 ──────────────────────────────────► 设备 (device 侧去重)
```

- **同一行、两条路**：DualSink 先写文件（USB 路径一字节不变、flush 语义不变），再对**同一帧**
  （`pet_transport.ensure_line` 的 bytes）做 TCP 发送；失败只降级不重排。**去重是设备侧职责**
  （同一事件会经 USB 与 TCP 各到一次，设备按事件内容/序去重——本次 host 不做去重）。
- **目标解析**（`resolve_tcp_target(tcp_arg, ip_file)`，每行事件时解析，IP 可后到）：
  1. `--tcp HOST:PORT` 字面量 → 直接用；
  2. `--tcp auto` → 读 ip-file 第一非空行（如 `192.168.31.198`）→ `host:8766`；
  3. 两者皆无 → None，静默跳过 TCP（纯 USB，行为与改造前一致）。
- **Best-effort 发送**（`tcp_send_line`）：每次连接（timeout 1 s）→ sendall → close，一行一连接；
  socket 整体 settimeout(1 s)，最坏 ~2 s 不阻塞轮询。任何异常被 DualSink 捕获，打**限频警告**
  （stderr，30 s 最多一条，注入 clock 可测），绝不崩 poller。
- **可注入**：`DualSink(tcp_send=...)` 注入发送函数（测试断言 target+line）；文件写失败照常抛出
  （USB 路径仍是一等公民，错误不吞）。

## 4. IP 发现（控制台 → ip-file）

- `file_to_serial.py` 在同一进程加 **daemon 读线程**（`console_reader`）：串口对象两线程只用
  **相反方向**（reader 只读、主循环只写），pyserial 支持该用法；真开串口加 `timeout=1.0`
  使 `readline()` 可超时返回。`--ip-file`（默认 `<log>.ip`）。
- 命中 `net: wifi connected ip=<ip>` → **tmp + os.replace 原子写** `<log>.ip`（内容一行 IP）；
  其余控制台行全部忽略（本任务不分发控制行）；每次公告覆盖重写（IP 变化取最新）；
  端口关闭/异常时线程退出，不影响写路径。poller 每行事件时重读 ip-file，设备后上线也能追上。
- supervisor 编排（`build_children`）：
  - poller 追加 `--tcp auto --ip-file <out>.ip`；
  - 桥追加 `--ip-file '<out>.ip'`（Windows 路径）；
  - 两侧指向同一个文件（`/mnt/d/buddy_flash/oc_events.log.ip` = `D:\buddy_flash\oc_events.log.ip`）。
