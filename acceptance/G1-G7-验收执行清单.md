## 2. 通用准备

### 2.1 构建与刷机

```bash
# 构建（构建目录必须在 WSL 原生盘）
cd firmware && source ../tools/idf-env.sh && idf.py -B ~/esp-build/buddy build && cd ..

# 打包并刷机（Windows 侧 esptool，走 COM5）
./tools/package-flash.sh
# 然后按 flash/README.md 在 Windows 侧执行 flash.ps1
```

### 2.2 起事件入口（HTTP → 串口）

**推荐：单进程桥**（自带串口写失败重连与丢弃记账）

```bash
python3 host/pet_bridge.py --serial COM5 --port 8765
```

打印 `bridge: http://127.0.0.1:8765/v1/events → COM5` 即就绪；`Ctrl-C` 退出时会打印
`发送 N，丢弃 M，重连 K` —— **G6 跑完必须核对 丢弃=0**。

**备选：两进程管道**（与原脚手架一致）

```bash
python3 host/pet_entry_server.py --port 8765 \
  | python3 host/pet_sender.py --port COM5 --stdin
```

> ⚠️ **200 ≠ 已送达**：串口不可用时入口仍回 200，但该行会被丢弃（桥会记账）。
> G6 的判定必须看屏幕，不能只看 HTTP 状态码。

### 2.3 直接发事件（不经 HTTP）

```bash
python3 host/pet_sender.py --port COM5 '{"version":1,"event":"task.done","title":"构建通过","project":"ci"}'
```

### 2.4 事件 → 宠物状态对照（G1 的依据）

| 事件 | 期望状态 | 备注 |
| --- | --- | --- |
| `agent.idle` | IDLE | |
| `task.start` / `agent.blocked` | WORKING / BLOCKED | |
| `agent.input_required` | INPUT | |
| `task.done` | DONE | 驻留 **5 s**、边沿去抖 **1.5 s** |
| `task.error` | ERROR | |
| 停主机 > **15 s** | OFFLINE（灰化） | `PET_LINK_TIMEOUT_MS` |

## 4. G1–G7 逐条

> 通用记录格式：`次数 | 期望 | 实测 | 对/错 | 时间戳`。每条门槛单独一个证据文件。

### G1 宠物 6 态（**20 次观测**；用户 2026-10-24 由 120 缩减）

| 步 | 动作 |
| --- | --- |
| 1 | 运行 `tools/g1-drive.py`（20 步固定序列，6 态全覆盖） |
| 2 | 每步目视：**进入态**正确，且**上一步的退出**正确；逐步入账 |
| 3 | OFFLINE 步需停发 ≥16 s；DONE 驻留需 6 s 以上 |

```bash
for i in $(seq 10); do
  python3 host/pet_sender.py --port COM5 '{"version":1,"event":"task.start","title":"G1"}'
  sleep 3
done
```

**判定**：**20/20 正确**（6 态全覆盖；用户 2026-10-24 缩减口径）。**当前证据**：无（只有零散目视，未按 10/10 记账）。

### G2 番茄钟（完成/暂停/放弃各 10/10；重启不丢 10/10）

> **必须先定口径**：25 min × 10 次 ≈ 4h10m，见 §6 `Q19`。以下按**测试构建**写。

```bash
# 测试构建：把专注缩到 30 s、休息 10 s（仅验收用，哈希必须登记）
cd firmware && source ../tools/idf-env.sh && \
  idf.py -B ~/esp-build/buddy-g2 \
    -DPOMO_FOCUS_MS=30000u -DPOMO_BREAK_MS=10000u build
```

| 子项 | 步骤 | 判定 |
| --- | --- | --- |
| 完成 | 开始 → 等响铃 → 按键进休息 → 等结束，10 次 | 10/10，且 `completed` 每次 +1 |
| 暂停 | 开始 → 中途短按暂停 → 等 2× 剩余时长，确认不动 → 继续 | 10/10，暂停期间剩余不变 |
| 放弃 | 开始 → 长按 → 确认回 IDLE 且统计不变 | 10/10 |
| 重启不丢 | 完成 3 次 → 断电 10 s → 上电读统计 | 10/10 次重启后数字一致 |

**注意**：release 构建还需**至少 1 次完整 25 min** 跑通，证明短时长没掩盖问题。

### G3 任务卡（20 次 ≤1 s 上屏；失败不剔除）

| 步 | 动作 |
| --- | --- |
| 1 | 发 20 次不同状态的任务事件，间隔 3 s |
| 2 | 用手机 120 fps 录像对准屏幕，逐条数帧差（或秒表目视，误差记 ±0.2 s） |
| 3 | 其中穿插 5 次 `task.error`，确认卡片**不消失**、只是变红/标错 |

**判定**：20/20 ≤1 s；失败卡 5/5 保留。

### G4 失联（20 次，≥19 次在 15–17 s 进入离线）

| 步 | 动作 |
| --- | --- |
| 1 | 设备在线，记 `t0`，立刻 `Ctrl-C` 停掉入口+发送端 |
| 2 | 秒表记到屏幕灰化的 `t1`，`t1-t0` 应落在 15–17 s |
| 3 | 恢复主机，确认状态回正；重复 20 次（每次约 25 s，全程 ~9 min） |

**判定**：≥19/20 在窗内。**测量起点须固定**（建议：发送端进程退出时刻）。

### G5 稳定性（插电连续 2 h）

```bash
# soak：每 30 s 一个事件，持续 7200 s；每 5 min 一个 done 用于目视确认"还活着"
python3 - <<'PY'
import json, subprocess, time
port = "COM5"
end = time.time() + 7200
i = 0
while time.time() < end:
    ev = "task.done" if i % 10 == 0 else "agent.idle"
    payload = json.dumps({"version": 1, "event": ev, "title": f"soak {i}"})
    subprocess.run(["python3", "host/pet_sender.py", "--port", port, payload],
                   check=False)
    i += 1
    time.sleep(30)
PY
```

记录：起止时间、需复位次数、掉线次数、发烫情况、屏幕异常。**判定**：0 次死机、0 次阻塞（事件仍能上屏）。

### G6 事件入口（20/20，1 s 内显示）

| 半段 | 状态 |
| --- | --- |
| host（20/20 送达 + 格式） | ✅ 已通过（`tools/gate-host-smoke.py`） |
| 设备（20/20 ≤1 s 上屏） | ⏳ 待跑 |

```bash
# 起管道后，另一个终端
for i in $(seq 20); do
  curl -s -o /dev/null -w "%{http_code} " -X POST \
    -H "Content-Type: application/json" \
    -d "{\"version\":1,\"event\":\"task.done\",\"title\":\"G6-$i\"}" \

done; echo
```

**判定**：20/20 状态 200 **且** 屏幕每次 1 s 内显示对应标题。

### G7 语音（各播报一次；20 次不重复、不误播）

| 步 | 动作 |
| --- | --- |
| 1 | 确认未静音（M6 菜单） |
| 2 | 混合触发 `input_required` / `task.done` / `task.error` 共 20 次，间隔 ≥5 s |
| 3 | 记录：是否播报、内容是否匹配、是否重复/漏播/误播 |

**判定**：20/20 正确，0 次重复、0 次误播。**注意**：`agent.idle` 不应触发播报。
