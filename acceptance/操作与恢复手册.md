> 目标读者：拿到本仓库 + 一块 **M5StickS3** 的人。按本文可完成：刷机 → 配置入口 → 日常使用 → 排障 → 退出/恢复 → 升级/回滚。
> 构建/开发环境见 `README.md`；验收结论见 `evidence/M9/2026-10-23-验收-G3G4G6G7.md`。

## 2. 首次刷机（Windows 侧，ESP-IDF v5.5.4）

1. 安装 ESP-IDF v5.5.4（本机路径 `D:\Espressif\frameworks\esp-idf-v5.5.4`）。
2. 同步源码到构建副本（**必须**，否则会刷到旧固件——缺陷 `B16`）：
   ```bash
   tools/sync-fw.sh          # 仓库 firmware → D:\buddy_flash\firmware
   ```
3. 构建 + 刷写（USB 连接设备，确认出现 `COM5`）：
   ```powershell
   D:\buddy_flash\build.ps1
   D:\buddy_flash\flash.ps1     # esptool，偏移 0x0/0x8000/0x10000
   ```
4. 串口控制台应出现 `AUDIO READY`、`立绘就绪`、`st: fps=7`。

> **产物可选**：`tools/package-flash.sh` 生成带 `flash/MANIFEST.txt` 的可移植烧录包。

## 3. 配置事件入口

- 入口：HTTP `POST http://127.0.0.1:8787/v1/events`（`PET_EVENT_PORT` 可覆盖）。
- 单进程桥（HTTP → 串口，带丢弃记账）：
  ```bash
  python3 host/pet_bridge.py --serial COM5 --port 8765
  ```
  退出时打印 `发送 N，丢弃 M，重连 K`；**丢弃必须为 0**。
- 事件体：`{"version":1,"event":"task.start","title":"…","project":"…","elapsed_s":12}`
  （多卡：加 `"tasks":[{…},{…}]`，≤3，新在上）。

## 4. 日常使用（设备按键）

| 模式 | KEY1 短按 | KEY1 长按 | KEY2 短按 | KEY2 长按 |
| --- | --- | --- | --- | --- |
| 值班 | 回终端窗口 | 静音开关 | 进番茄钟 | 菜单 |
| 番茄钟 | 开始/暂停/继续 | 放弃 | 回值班 | 菜单 |

- 完成/失败/需要确认：各播报一次（"都做完啦 / 出错啦 / 需要你确认一下"）。
- 值班休闲：久坐 → 无聊小动作 → 犯困 → 熄屏（夜间 23–07 且时间已知时）；任意键唤醒。
- 状态查看：串口控制台 `st: fps=… muted=… phase=… done=… focus_s=… lei=…`（**每 10 s**）。

## 5. 问题定位

| 现象 | 先查 | 处理 |
| --- | --- | --- |
| 卡片不显示 | 桥的"丢弃"计数、`top=` 日志 | 丢弃>0 → 串口被占用/断开；重启桥 |
| 宠物灰屏 | 是否 >15 s 无任何事件 | 入口/桥是否在发心跳；恢复发一条事件即回正（缺陷 B17 已修） |
| 没有声音 | `muted=`、音量 | KEY1 长按切静音；确认 `AUDIO READY` |
| 刷机失败 | `COM5` 是否出现 | 重插 USB；关闭占用串口的脚本 |
| 事件 200 但屏无变化 | 入口回了 200 ≠ 已送达 | 看桥的丢弃计数与设备 `link parse err` |

## 6. 退出 / 恢复

- **正常退出**：停止 `pet_bridge.py`（Ctrl-C）→ 拔 USB 即可；设备断电不丢统计（NVS）。
- **清空统计**：菜单无此功能 → 用 `esptool erase_region` 清 NVS 分区，或整片擦除后重刷（见下）。
- **恢复出厂 / 整片重刷**（会清空 NVS 统计）：
  ```powershell
  python -m esptool --chip esp32s3 -p COM5 erase_flash
  D:\buddy_flash\flash.ps1
  ```
- **仅回滚固件**：用带偏移的 `write_flash` 刷入备份镜像（`acceptance/manifest.json` 的 `build.artifacts` 有偏移与哈希）：
  ```powershell
  python -m esptool --chip esp32s3 -p COM5 write_flash 0x0 bootloader.bin 0x8000 partition-table.bin 0x10000 <备份的 esp32_buddy.bin>
  ```

## 7. 升级

1. `git pull` → `tools/sync-fw.sh` → `build.ps1` → `flash.ps1`。
2. 升级后：`make-manifest.py --build-dir <build>` 更新 manifest；跑 `tests/run.sh` + `tools/gate-host-smoke.py` 自检。
3. **回滚路径**：保留上一版 `esp32_buddy.bin`；按 §6"仅回滚固件"刷回。

## 8. 明确不承诺

- 不承诺跨崩溃 exactly-once；入口进程崩溃不自动重启（交给外部 supervisor）。
- 不承诺 tag/Release（需另行授权）。
- 时延口径含 USB 链路（见 `contracts/M9-验收测量契约.md`）。

## 9. 入口守护与 `/esp32-buddy`（v1.1.0）

- 启动（幂等）：`bash tools/esp32-buddy-up.sh`；查看：`bash tools/esp32-buddy-status.sh`；停止：`bash tools/esp32-buddy-down.sh`
- OpenCode 里输入 **`/esp32-buddy`** 即启动并报告守护状态
- 守护内容：轮询器（OpenCode DB → `oc_events.log`）+ Windows 串口桥（→ COM5）；崩溃后指数退避重启（1→30 s）
- 日志：`/tmp/esp32-buddy.log`；子进程状态：`/tmp/esp32-buddy.state`

### WiFi / NTP 接入（口令不进仓库）

任选其一（写入设备 NVS，立即生效）：
```bash
# A. 守护运行中：追加到桥的输入文件（会被写入 COM5）
echo '{"version":1,"cmd":"wifi.set","ssid":"你的SSID","password":"你的密码"}' >> /mnt/d/buddy_flash/oc_events.log

# B. 停止守护后用一次性发送（Windows python + pyserial）
python -m esptool ...   # 不需要；用任意串口发送脚本写一行即可
```
- 查询：`{"version":1,"cmd":"wifi.status"}` → 日志 `net: status ssid=… ip=… hour=…`
- 清除：`{"version":1,"cmd":"wifi.clear"}`
- 同步成功日志：`net: wifi connected ip=…` + `net: sntp synced hour=…`
- 未验证声明：v1.1.0 发布时**未提供凭据**，连接/授时路径未真机验证。
